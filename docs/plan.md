## 基本セット（2026-11-22 フェーズ2で決定）

判定は Claude Docs「Gateway Garden フェーズ2 基本セットの札」 https://claude.ai/artifact/WfLKeTMewBqHzh1tpbW7m5 。札は `expansions/base/cards.json`（数字は仮、フェーズ3・8で直す）。

- 住人30種類（5色×6役目が1種類ずつ）。山は各種類2枚。
- 色の個性：白＝場所、赤＝固まる、青＝流れ、緑＝晩成、黄＝貯める。拡張の色の個性はその拡張しだい。
- 効果の読み方8つ（`CONTRIBUTING.md`）。8つ目の「好きなときに使う効果（`use`）」と「札を動かす（`move`）」は人の要望で足した（再配置の札の構想）。
- 目標札8枚（そろいの花壇・虹の小道・四つ角の守り・大きな木・茂った庭・五色の庭・仲良しの輪・対の芽）。1ゲーム3枚。「違う出身が3枚つながる」は最初の拡張と一緒に足す。
- 最初の拡張は auto-battler（フェーズ6）。

残りのメモ：#1 黄の「上限+」が効くか（フェーズ3で測る）、#2 好きなときに使う効果の処理と CPU（フェーズ3）。

## ルールの心臓部と自動対戦（2026-11-22 フェーズ3）

- `src/core/game.js`（手番・効果の列と選ぶ所・連鎖・上限・目標札・得点）、`src/core/cpu.js`（CPU ふつう）、`src/core/goals.js`、`tools/simulate.mjs`（`node tools/simulate.mjs 300 2,3,4 8 --out …`）。
- 測った前提：全員 CPU「ふつう」（その場で一番得な手、use は使わない）、基本セットだけ、各札2枚、8ラウンド、各人数300ゲーム。結果は `docs/sim/phase3-final.md`。`phase3-base.md`・`phase3-growth-b/c.md` は直す前の CPU で測った比べ用。
- 人の判定で決めたこと：育てる値段をB案（早熟1・3、平ら2・3、晩成3・4）に上げた。黄の「上限+」を「終わりに残った素材○個につき1点」（部品 `hoard`）に替えた。
- 結果（4人）：点の平均26.8（1位34.3）、内わけは段階11.8・終わりの効果5.7・目標札9.3。庭は7.3枚で段階3は3.9枚。席ごとの1位は23〜27%。操作の数は2人68・3人101・4人136。
- 長さの見積もり：拾う手番30秒、反応フェーズ1回75秒とすると、2人で約18分、4人で約26分。企画の30〜60分より短めなので、フェーズ4で人が遊んで測る。
- 残り：#2 CPU が use を使う（フェーズ4）、#3 使えない色が余る（フェーズ4で決める）、#4 札の強さの差、#5 目標札の取りやすさ（フェーズ8）。

### 試し遊びの結果と直したこと（2026-11-22）

人が3人戦を3回（記録はチャットに貼られた。かかった時間は約17分・14分・21分）。感想：ちゃんとゲームになっている、CPU に勝てない、悩む所が多くて良い、3人で約20分（30分に収まる）。#3 は「変換が生きるので、使えない色はあるべき」で直さない。

| 直したこと | 前 | 後 |
| --- | --- | --- |
| 反応フェーズで得た魔素（D3） | 次のラウンドから | その場で使える |
| 育てる値段の下限（読み方4） | 最低1個 | 0個まで |
| 札を取る枚数 | 1回の拾いで1枚 | 2枚まで、2枚目は任1が足される（札が消える効果を入れたときに埋め直せる） |
| 保持 | 取った札はそのラウンドに全部置く | 2枚まで置かずに持っておける（置いたときの効果をずらせる）。置かずに終われば0点 |
| やり直し | なし | 反応フェーズの自分の操作を「1つ戻す」。ラウンドを終えて全員がそろうまで戻せる |
| 「任」の払い | 自動 | 払う色を選べる |
| 庭番カメ | 段階1 隣-1、段階2・3 も実質同じ | 段階1 隣の白い札-1、段階2 隣-1、段階3 同じ行と列-1 |

2回目の試し遊び（3人戦、約30分。途中で問題を書きながら）で直したこと：

- 反応フェーズ中は、ほかの人の庭・魔素・点・目標札・できごとを、反応フェーズが始まった時のまま見せる。ほかの人がしたことはラウンドが終わってからまとめて出す（後出しを防ぐ）。**通信対戦（フェーズ5）でも、反応フェーズ中はほかの人の庭を送らない。**
- 上の帯に「拾う順（今の人を色付け）」と「次のラウンドの先番」を出す。
- 選ぶ所で、効果を出している札を光らせ、名前とマスを書く（エンジンの choice に source）。
- 最後のラウンドの終わりは、上限を超えた魔素を選ばずに捨てる（色は点に関わらない）。
- 後で：#6 ペンで落書き、#7 言葉の整理（フェーズ7）、#8 札の一覧（フェーズ6）。

直した後の自動対戦（`docs/sim/phase4-rules.md`、各人数200ゲーム）：庭は約8.3枚（前7.3）、段階3は約4.1枚、点の平均は約3点上がった。目標札は全体に取りやすくなった（四つ角の守り 94%）。調整はフェーズ8。

## 通信対戦（2026-11-22 フェーズ5）

- 最初の画面で「1人で遊ぶ」「部屋を作る」「部屋に入る」を選ぶ。部屋は合言葉で入る（作る人に6文字の案が出る）。人が足りない席は CPU。
- つなぎ方：Trystero 0.26.0（jsDelivr から読み込む。nostr の公開中継を使う）。つながりにくいときは URL に `?net=torrent` や `?net=mqtt` を付ける。部品は `src/net/trystero.js`。ほかのつなぎ方（Tailscale 用サーバー）は同じ形（selfId・on・send・onJoin・onLeave・leave）を返せば差し替えられる。
- ホストのブラウザが本物の状態を持つ（`src/net/session.js` の GameHost・HostRoom）。ほかの人には「その人から見た盤面」（`src/core/view.js`）だけを送る：山の並びと乱数は送らない、反応フェーズ中はほかの人の庭・魔素・目標札を反応フェーズが始まった時のまま。できごとも人ごと（`src/net/journal.js`）。
- 参加者（GuestClient）は届いた盤面を描き、操作をホストに送るだけ。席はホストが決めるので、ほかの席の操作は送れない。
- 版：`src/version.js` の APP_VERSION（package.json と同じ）と札の版がホストと違うと入れない。ルール・画面・やりとりを変えたら上げる。
- 抜けた人の席は CPU が代わりに遊ぶ。同じブラウザ（同じ印）で同じ合言葉に入り直すと席に戻れる。ホストが抜けるとゲームは続けられない。
- 確かめたこと：にせの通信で「ホスト＋参加者＋CPU で最後まで」「版違いは入れない」「抜けて戻る」「なりすませない」（テスト）。本物の Trystero で、ブラウザの2つのタブ（ホストと参加者）が6ラウンドを最後まで遊べた。
- まだ：別々のパソコン・別々の回線どうしで遊ぶのは人に試してもらう。記録のコピーはホストだけ。
- 人の試し（2026-11-22、スマホとパソコン・同じ回線）：つながった（最初は約1分）。番の操作の遅れは気にならない。抜けて戻るもできた。入り直しが早いのは、ページの中で中継とのつながりが残るため。別の回線・遠くの人とは夜に試す。
- 後で（フェーズ6）：#9 部屋の流れ（つないでからゲームセットを選ぶ → 終わったら部屋に戻って次のゲーム）、#10 投了、#11 最初につながるまでの時間。

## 作りの方針

- `src/core/`：ルールの心臓部。画面と通信から切り離した純粋な関数（状態＋操作 → 新しい状態）。乱数は種つきで、同じ種なら同じ結果になる。CPU とテストもここを使う。
- `src/net/`：つなぎ方。`Transport`（送る・受け取る・入退室）の形をそろえ、Trystero 版とローカル版（同じ画面で CPU と遊ぶ）を作る。
- `expansions/<id>/`：拡張ごとのフォルダ。`expansion.json`（名前・版・作者）と `cards.json`（住人の札）。効果は決まった部品の組み合わせで書く。
- `tools/validate-expansions.mjs`：拡張データの書き方を確かめる。CI でも動かす。
- 通信対戦の始めに、使う拡張の id と版を全員でそろえる（違えば入れない）。
