# Gateway Garden 計画のメモ

企画の正は Claude Docs「ボードゲーム 企画まとめ（引き継ぎ用）」 https://claude.ai/artifact/KfkF25g823AE6HSda3pvn4 。決まったことは企画まとめにも書き足す。

## 決まったこと（2026-11-22）

| 項目 | 決めたこと |
| --- | --- |
| ゲーム名 | Gateway Garden（世界をつなぐ庭） |
| テーマ | 素材＝5色の魔素（白・赤・青・緑・黄）、札＝別の世界から来た住人。住人の出身＝過去作（1作＝1拡張） |
| 公開 | GitHub Pages（静的 HTML）。サーバーは持たない |
| 通信対戦 | Trystero でブラウザ同士をつなぐ。ホストのブラウザが進行役、他の人は操作だけ送る |
| 通信の作り | つなぎ方を差し替えられる形（`src/net/`）。あとで Tailscale 用のサーバー版を足せる |
| 共同編集 | 札を足す人はブランチで Pull Request。GitHub Actions が拡張データとテストを確かめる |

## 作りの方針

- `src/core/`：ルールの心臓部。画面と通信から切り離した純粋な関数（状態＋操作 → 新しい状態）。乱数は種つきで、同じ種なら同じ結果になる。CPU とテストもここを使う。
- `src/net/`：つなぎ方。`Transport`（送る・受け取る・入退室）の形をそろえ、Trystero 版とローカル版（同じ画面で CPU と遊ぶ）を作る。
- `expansions/<id>/`：拡張ごとのフォルダ。`expansion.json`（名前・版・作者）と `cards.json`（住人の札）。効果は決まった部品の組み合わせで書く。
- `tools/validate-expansions.mjs`：拡張データの書き方を確かめる。CI でも動かす。
- 通信対戦の始めに、使う拡張の id と版を全員でそろえる（違えば入れない）。

## フェーズ

1フェーズは1〜2日。フェーズの終わりに人が遊び、番号と理由で答える。残りの Issue を読み上げてから閉じる。

| # | 内容 | 終わりの確かめ |
| --- | --- | --- |
| 0 | 準備：リポジトリ・CI・Pages・計画 | CI が通る、Pages が開く |
| 1 | 未決事項を決める：役目の中身、効果の部品、隣接の部品、勝利点の獲得条件、数の目安 | 企画まとめに書き足す |
| 2 | 基本セットの札の表（Docs で判定）。拾い方を曲げる効果を数枚。札ごとに「いちばん素直な札ではできないこと」 | 表に全部 OK |
| 3 | ルールの心臓部＋テスト＋CPU どうしの自動対戦（勝ち筋の数・長さを測る） | 自動対戦の結果を報告 |
| 4 | 試作画面（1人＋CPU）。数枚の札で遊ぶ | 人が遊んで判定 |
| 5 | 通信対戦（Trystero・部屋の合言葉・版そろえ・抜けた人の扱い） | 2台で1回通して遊ぶ |
| 6 | 拡張の仕組み（札一覧ページ・CONTRIBUTING）＋最初の拡張 | PR で札を足す手順を人が試す |
| 7 | 見た目（可愛い方向）。試し描きを数個見せてから量産 | 判定 |
| 8 | 調整（前提を決めてから、まとめて合わせて固定） | 自動対戦とテストで守る |
| 9 | ふり返り | `docs/retrospective.md` |

## 未決事項（企画まとめより）

- 拾い方を曲げる効果の中身（基本セットに何種類、何段階から使えるか）
- 役目の中身と、効果の部品の一覧
- 隣接の条件をどう部品に分けるか
- 勝利点の獲得条件（目標札・段階・お題・一番乗り）
- 数の目安：ラウンド数、束の数（4〜5）、場の札の枚数、素材の上限、札の値段の幅
- 9マスが埋まった後に札を取ったとき
- 先番がラウンドごとに回るか
- 基本セットに入れる札と、最初に作る拡張
- 長さを開始時に選べるか
- ゲームをまたいで解放が進む形を入れるか
- CPU の強さの段階
- 素材と札の見た目
